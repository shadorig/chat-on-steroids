## 2.0.10

This is a security update for Local Projects. Update the desktop app and reload the matching
companion extension together.

- Local Project filesystem authority is now independent of transcript/session metadata and is
  committed in a fail-closed durable ledger with exact session/conversation bindings.
- A chat bound to one Local Project can no longer reach an absolute path, search target, patch
  destination, download destination or explicit command starting directory in a sibling folder just
  because both folders are under the same approved parent root.
- Project identity is established before exact browser request correlation can admit project-aware
  filesystem work. Fresh sends that lose the browser page in the narrow post-Send/pre-receipt gap
  remain blocked by a durable unresolved-send fence until exact ownership is settled or safely
  aborted.
- Legacy Local Project state migrates conservatively. Positive ownership is retained; ambiguous or
  unavailable authority fails closed instead of silently widening to an approved root.
- **Remove project** still only ungroups the folder in the sidebar. Existing conversations keep their
  project scope, and re-adding the same folder restores the same identity. The explicit security
  reset is the destructive recovery path and starts a new authority era.
- Companion bridge protocol 14 is required for the project-input claim/fence handshake. Version
  2.0.9 used protocol 13, so the desktop app and companion extension must both be updated to 2.0.10.

**Reload the matching companion extension and refresh the connectors in ChatGPT after updating.**

The native source download accompanies the installers and is covered by the release checksums.
Installed notices link to it and explain the LGPL/MPL components and library replacement.

> **macOS:** publisher-unsigned and unnotarized; verify the checksum. Requires macOS 13 Ventura or newer. Ad-hoc sealing provides bundle integrity, not publisher trust.
> **Linux:** prefer the DEB on Debian/Ubuntu. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

Core and the workspace support Windows, macOS and Linux. Desktop screen/input control is available
on Windows and optionally macOS with Screen Recording and Accessibility permissions. External
plugins run with their own OS or service permissions and do not inherit approved-folder
restrictions. Hosted-service terms and account limits apply. This project remains beta.
